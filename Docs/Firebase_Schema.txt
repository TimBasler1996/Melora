# Firebase Schema (source of truth)

This document describes the Firestore / Storage structure SocialSound uses.
If code changes the schema, update this file AND `firestore.rules` /
`firestore.indexes.json` / `storage.rules` in the repo root. Deploy with:

    firebase deploy --only firestore,storage,functions

Auth is Firebase *anonymous* auth: `uid` is the device's anonymous user.

## users/{uid}
One document per user. Written by the owner only (rules), readable by any
signed-in user (Discover, chat headers, likes).

Profile:
- `firstName`, `lastName`, `city`, `gender`: String
- `birthday`: Timestamp
- `lookingFor`: String (optional)
- `displayName`: String — "First Last", kept in sync by `saveBasics`
- `firstNameLower`, `lastNameLower`, `displayNameLower`: String — lowercase copies for prefix
  search. Written by the client and re-derived by the `onUserWritten` Cloud
  Function so older profiles stay searchable.
- `photoURLs`: [String] — 2…5 real URLs, index 0 is the profile photo
- `heroPhotoURL`: String (optional) — uncropped hero image
- `avatarURL`, `spotifyAvatarURL`: String (optional, legacy / Spotify)
- `spotifyId`, `spotifyCountry`, `countryCode`: String (optional)
- `profileCompleted`: Bool, `completedAt`: Timestamp

Presence:
- `isBroadcasting`: Bool
- `currentTrack`: { id, title, artist, album?, artworkURL?, durationMs? }
- `lastLocation`: { latitude, longitude }
- `lastActiveAt`, `createdAt`, `updatedAt`: Timestamp
- `broadcastMinutesTotal`: Int
- `likesReceivedCount`: Int — maintained by the `onLikeCreated` function;
  shown on other users' profiles (their `likesReceived` is not listable)
- `fcmToken`: String — push token, written by AppDelegate
- `deletionRequestedAt`: Timestamp — set by the app when the user deletes
  their profile; the `onUserWritten` function then removes the user doc,
  photos, follows, blocks, broadcast, conversations and the auth user
- `spotifyTaste`: { topArtists, topTracks, playlists: [{ id, name, subtitle?,
  imageURL?, url? }], updatedAt } — copied from Spotify by the app at most
  once a day (public playlists only); shown as "Music taste" on the profile
- `spotifyTasteHidden`: Bool — Settings switch "Music taste on my profile"
  off: the app deletes `spotifyTaste` and stops syncing it
- `notifyLikes`, `notifyMessages`, `notifyFollowers`: Bool — mirrored from
  Settings; missing means enabled. Cloud Functions skip the push when false.

### users/{uid}/likesReceived/{likeId}
A like (optionally with a message) this user received. Created by the liker,
status updated by the owner.
- `fromUserId`, `toUserId`, `trackId`, `trackTitle`, `trackArtist`: String
- `trackAlbum`, `trackArtworkURL`, `placeLabel`: String (optional)
- `latitude`, `longitude`: Double (optional)
- `fromUserDisplayName`, `fromUserAvatarURL`: String (denormalised)
- `message`: String (optional, ≤160 chars)
- `status`: "pending" | "accepted" | "rejected"
- `createdAt`, `respondedAt`: Timestamp

### users/{uid}/likesGiven/{likeId}
Mirror of the like for the liker (same document id, same fields). Written
atomically with `likesReceived`. The receiver may only update `status` /
`respondedAt`. The `onLikeAccepted` function watches this collection.

## broadcasts/{uid}
"User is broadcasting a track". Document id = broadcaster uid, so there is
at most one live broadcast per user. Owner-only writes.
- `userId`, `trackId`, `trackTitle`, `trackArtist`: String
- `trackAlbum`, `trackArtworkURL`, `spotifyTrackURL`: String (optional)
- `latitude`, `longitude`: Double (optional) — snapped to a ~275 m grid on
  the device before upload (`LocationPoint.fuzzed()`); never precise
- `isLive`: Bool — false once the broadcast ended
- `broadcastedAt`, `updatedAt`, `endedAt`: Timestamp (server time)

Lifecycle: the client refreshes `updatedAt` every 15–20 s while live and
sets `isLive: false` + `endedAt` on stop (the document is kept). Discover
shows live docs refreshed within 5 min as "Live now" and everything else
from the last 24 h as "Recently live". The `expireStaleBroadcasts`
function marks live docs older than 10 min as ended (covers apps killed
mid-broadcast) and deletes docs older than 24 h.

## conversations/{conversationId}
Chat between two users. Id = the two uids, lowercased and sorted, joined with
"_" (see `ChatApiService.conversationId`). Participants only.
- `participantIds`: [String] (exactly 2, immutable)
- `status`: "pending" | "accepted" | "rejected" (missing = accepted)
- `initiatorId`: String — who sent the first message / request
- `createdFromLikeId`, `createdFromTrackId`: String (optional)
- `lastMessageText`, `lastMessageSenderId`: String
- `lastMessageAt`, `createdAt`, `updatedAt`: Timestamp (server time)
- `lastReadAt`: { uid: Timestamp } — per-participant read marker

Deleting the document triggers `onConversationDeleted`, which removes the
messages subcollection.

### conversations/{conversationId}/messages/{messageId}
- `senderId`: String (must equal the writer's uid)
- `text`: String
- `type`: "text"
- `createdAt`: Timestamp (server time)
- `replyTo`: { messageId, senderId, textPreview } (optional)
- `reactions`: { uid: emoji } — the only field that may change after send
- `track`: { id, title, artist, album?, artworkURL?, durationMs? } (optional) —
  a song sent from the composer; `text` then holds "🎵 Title – Artist" for
  previews and pushes

## follows/{followerId_followingId}
- `followerId`, `followingId`: String
- `createdAt`: Timestamp
The `onFollowCreated` function pushes "X started following you" to the
followed user (type `newFollower`, `userId` = follower).

## reports/{reportId}
Write-only for users (rules deny reads); `onReportCreated` logs each one to
Cloud Logging as `report.received` until there is a review tool.
- `reporterId`, `reportedUserId`: String
- `reason`: spam | inappropriate_photos | harassment | fake_profile | underage | other
- `details`: String (≤ 500 chars, may be empty)
- `createdAt`: Timestamp

## blocks/{blockerId_blockedUserId}
Private to the blocker; hides the blocked user from Discover, Chats and search.
- `blockerId`, `blockedUserId`: String
- `createdAt`: Timestamp

## Storage
- `userPhotos/{uid}/photo_{index}.jpg` — profile photos (owner writes)
- `userPhotos/{uid}/hero_photo.jpg` — hero image

## Auth
Everyone starts as an anonymous Firebase user. "Keep your profile" (last
onboarding step, and Settings → Account) links a Sign in with Apple
credential to that uid so the account survives reinstall. If the Apple ID
already owns an account, the app signs into that one instead.

## Composite indexes (firestore.indexes.json)
- `broadcasts`: isLive ASC, updatedAt ASC
- `likesGiven`: status ASC, respondedAt DESC
- `follows`: followingId ASC, createdAt DESC
- `conversations`: participantIds CONTAINS, updatedAt DESC
